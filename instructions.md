# Steam Farm Hours — инструкция

Плагин **Steam Farm Hours (Dim4n4ik Shop)** автоматизирует продажу фарма часов Steam через FunPay и API `dim4n4ik.shop`.

После оплаты заказа плагин сам:

- определяет привязанный FunPay-лот;
- проверяет подписку и свободные места;
- запрашивает у покупателя логин Steam;
- запрашивает пароль и Steam Guard, если он нужен;
- получает AppID игр от покупателя либо использует игры, заранее заданные продавцом;
- запускает фарм на оплаченное время;
- останавливает фарм после завершения заказа;
- освобождает место в подписке;
- ведёт активные заказы, историю и статистику;
- при возврате средств на FunPay останавливает фарм.

> Плагин работает только с режимом фарма **часов Steam**.

## Что понадобится

Для работы нужны:

1. Установленный **FunPay Cardinal**.
2. Плагин `Steam Farm Hours` в формате `.py`.
3. API-ключ сервиса `dim4n4ik.shop`.
4. Активная подписка на фарм часов.
5. FunPay-лот, который будет привязан к плагину.

## Установка плагина

1. Скачайте файл плагина `.py` из репозитория.
2. Откройте Telegram-бота своего FunPay Cardinal.
3. Перейдите в раздел **Плагины**.
4. Загрузите файл `Steam Farm Hours`.
5. Откройте установленный плагин.

Также меню можно открыть командой:

```text
/steamfarm
```

После установки откроется главное меню плагина.

## Настройки одного лота

Для каждого лота задаются следующие параметры.

### 1. Время за одну покупку

Пример:

```text
2
```

Если установить `2`, то:

- 1 шт. = 2 часа фарма;
- 2 шт. = 4 часа;
- 3 шт. = 6 часов.

### 2. Максимум игр

Определяет, сколько AppID покупатель сможет указать для одного заказа.

Например:

```text
3
```

Покупатель сможет отправить максимум три игры.

### 3. Кто выбирает игру

Доступно два варианта.

**👤 Выбирает покупатель**  
После подключения Steam плагин попросит покупателя отправить AppID.

**🎮 Задаёт продавец**  
AppID заранее закрепляются за лотом, и покупателю не нужно выбирать игры самостоятельно.

Пример AppID Counter-Strike 2:

```text
730
```

Несколько AppID указываются через пробел:

```text
730 570
```

### 4. Скрытый онлайн

Можно выбрать, должен ли Steam-аккаунт запускаться в скрытом режиме.

### 5. Состояние лота

В карточке лота отображается одно состояние:

- `🟢 включён` — лот активен;
- `🔴 выключен` — отключён вручную;
- `🟠 авто-пауза` — временно выключен автоматикой;
- `🟡 синхронизация` — состояние обновляется;
- `⚪️ неизвестно` — FunPay не удалось проверить.

### 6. Доступное количество

Плагин рассчитывает, сколько единиц товара можно безопасно продавать сейчас, учитывая:

- оставшееся время подписки;
- запас до окончания подписки;
- лимит Steam-аккаунтов тарифа;
- занятые и зарезервированные места;
- количество часов за одну единицу товара;
- лимит игр тарифа.

При необходимости нажмите:

```text
🔄 Пересчитать
```

## Как проходит заказ

Обычный сценарий выглядит так.

### 1. Покупатель оплачивает заказ

Плагин определяет лот, количество товара и общее оплаченное время.

### 2. Проверяется возможность запуска

Плагин проверяет:

- активность подписки;
- срок действия подписки;
- свободные места;
- лимит игр;
- доступное безопасное время.

### 3. Покупатель получает сообщение

Если заказ можно запустить, плагин просит отправить логин Steam.

### 4. Покупатель отправляет пароль

После логина плагин запрашивает пароль Steam.

Пароль используется для подключения аккаунта через API и не сохраняется в постоянном состоянии плагина.

### 5. Steam Guard

Если Steam требует подтверждение, покупателю приходит запрос одноразового Steam Guard-кода.

### 6. Выбор игр

Если для лота установлен режим **«выбирает покупатель»**, плагин попросит AppID.

Если игры заранее заданы продавцом, этот шаг выполняется автоматически.

### 7. Запуск

После успешного подключения плагин запускает фарм и сообщает покупателю:

- выбранные игры;
- оплаченное время;
- плановое время окончания.

### 8. Завершение

Когда оплаченное время заканчивается, плагин:

1. останавливает фарм;
2. отключает аккаунт от farm API;
3. освобождает место;
4. переносит заказ в историю;
5. отправляет покупателю сообщение о завершении.

## Очередь заказов

Очередь включается здесь:

```text
⚙️ Настройки плагина → 🛡 Безопасность → 🕒 Очередь
```

Если очередь включена и все места тарифа заняты, новый заказ может быть поставлен в очередь вместо немедленного запуска.

Покупателю сообщается его позиция.

Когда место освобождается, плагин автоматически переводит следующий заказ к этапу подключения Steam и пишет покупателю.

## Автодеактивация лотов

Настройка находится в:

```text
📦 Заказы → 🎟 Автодеактивация
```

Если свободных мест на тарифе нет, плагин может временно выключать управляемые лоты FunPay, чтобы не принимать новые заказы, которые нельзя запустить.

Когда место снова появляется, доступность лотов пересчитывается автоматически.

---

## Автовозврат

Настройка находится в:

```text
📦 Заказы → ↩️ Автовозврат
```

Если автовозврат включён, плагин может вернуть заказ до запуска фарма при некоторых проблемах, из-за которых услугу нельзя безопасно выполнить, например:

- нет активной подписки;
- невозможно определить срок подписки;
- до окончания подписки недостаточно времени;
- лимит игр лота превышает возможности тарифа.

Занятый слот сам по себе не относится к этим причинам: для него можно использовать очередь и автодеактивацию.

---

## Возврат средств на FunPay

Если продавец вручную делает возврат по заказу, плагин реагирует на статус FunPay.

При полном или частичном возврате он пытается:

1. немедленно остановить фарм;
2. удалить Steam-аккаунт из farm API;
3. освободить место;
4. отметить заказ как возвращённый.

Если API временно не подтвердил остановку, заказ переводится в состояние повторной остановки и плагин продолжает попытки.

## Частые проблемы

### Лот не включается

Проверьте:

1. Добавлен ли API-ключ.
2. Активна ли подписка.
3. Есть ли свободное место по тарифу.
4. Не превышен ли лимит игр.
5. Достаточно ли времени до окончания подписки.
6. Включена ли привязка самого лота.

После этого нажмите **🔄 Пересчитать**.

### Пишет «нет свободного места», хотя место должно быть

Откройте логи плагина и найдите запись проверки слотов.

Плагин отдельно учитывает:

- количество аккаунтов, которое вернул API;
- временные резервации во время подключения Steam;
- итоговое занятое количество;
- количество свободных мест.

Заказ, который только ждёт логин покупателя, сам по себе не должен занимать слот.

### Покупатель не получает сообщение

Проверьте:

- привязан ли заказ к настроенному лоту;
- включён ли плагин;
- не возникла ли ошибка FunPay в логах;
- корректно ли определился чат покупателя.

### Неверный Steam Guard

Покупатель может отправить новый одноразовый код.

Если сессия входа истекла, плагин снова попросит пароль и начнёт подключение заново.

### Неверные AppID

Нужно отправлять только числовые AppID через пробел.

Пример:

```text
730 570
```

Количество игр не должно превышать лимит, заданный в лоте и тарифе.

### Фарм не остановился после возврата

Откройте карточку заказа и логи.

Если API не подтвердил остановку сразу, плагин сохраняет заказ для повторной попытки остановки.
